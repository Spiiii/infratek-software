# P5.7-E1 — Controlled retrieval evaluation runner

## Mục tiêu

CLI này chuẩn bị và ghi evidence cho core retrieval eval 120 câu. Nó tái sử dụng query embedding, vector repository, FTS repository, hybrid retrieval và RRF hiện có. E1 chỉ triển khai và kiểm thử offline; chưa chạy live retrieval.

## Chạy dry-run

Dry-run là mặc định và không khởi tạo Payload, database hay provider:

```powershell
npm run eval:chat:retrieval -- --run-id p57e-plan-01 --max-cases 3
```

Output mặc định:

```text
$env:TEMP\infratek-p5.7e\<run-id>\retrieval-evidence.json
```

Có thể chọn case bằng cách lặp `--case-id`:

```powershell
npm run eval:chat:retrieval -- --run-id p57e-plan-02 `
  --case-id chat-eval-ans-001 `
  --case-id chat-eval-mis-001 `
  --max-cases 2
```

`--output-dir` phải là absolute path nằm ngoài repository. File dùng chế độ tạo mới (`wx`), nên một run ID/output đã tồn tại không bị ghi đè.

## Live guard dành cho P5.7-E2

Live mode chưa được chạy trong E1. Nó chỉ hợp lệ khi có đồng thời:

- `--live`;
- ít nhất một `--case-id` cụ thể;
- `--max-cases` dương;
- `--max-embedding-calls` dương và không nhỏ hơn `--max-cases`;
- output nằm ngoài repository.

Runner từ chối full 120-case live run. Mỗi case chỉ đi qua `retrieve()` một lần; adapter hiện có đặt automatic retry bằng 0, query rewrite bằng 0 và generation call bằng 0. Khi budget hết, runner dừng. Owner sẽ duyệt batch và call budget thật ở E2.

## Pipeline được tái sử dụng

Live executor ghép đúng các thành phần hiện có:

1. `createLiveQueryEmbeddingAdapter()` — tối đa một physical embedding call/case.
2. `VectorRetrievalRepository` — top 20.
3. `FtsRetrievalRepository` — top 20.
4. `retrieve()` và `fuseCandidates()` — RRF với `k=60`.
5. Final top 6.

Runner không gọi chat orchestrator, decision policy hoặc generation adapter. Vì vậy nó không thay đổi `UN-CALIBRATED`, không bật production `ANSWER`, và không đi qua public Turnstile/Upstash quota.

## Evidence contract

`retrieval-evidence.json` chứa:

- run ID, timestamp và dataset version;
- expected decision và SHA-256 query identity cho từng case;
- trạng thái execution/retrieval;
- embedding model/version/dimension; ingestion/prompt/threshold version;
- vector top 20, FTS top 20, toàn bộ merged RRF ranking và final top 6;
- source identity, public URL, rank, distance/score nếu có;
- latency, diagnostics và error category đã sanitize;
- call budgets: embedding, rewrite, generation và retry.

RRF score chỉ là tín hiệu xếp hạng, không phải xác suất hoặc confidence. Runner không tạo semantic relevance label, không ghi API key, connection string, raw header, provider body hoặc raw question.

## Tái sử dụng ở P5.7-F

Artifact live đã ghi sẽ được đọc lại khi calibration để tránh gọi embedding lần nữa. Chỉ chạy lại retrieval khi dataset question, embedding model/version hoặc indexed content/version thay đổi.

## Giới hạn

- E1 chưa chứng minh provider quota hoặc latency live.
- Retrieval candidate không chứng minh câu trả lời đúng.
- Citation, grounding và generation không nằm trong runner retrieval-only này.
- Live E2 vẫn cần preflight xác nhận Neon `phase3-preview`, cấu hình version và owner-approved call budget.

## E1.1 — Sửa bootstrap live runner

Smoke E2 đầu tiên dừng trước provider/database vì native Node type stripping không resolve được các import TypeScript không có extension trong `payload.config.ts` (bắt đầu tại `src/collections/Authors`). Production Payload config và collection imports vẫn đúng với toolchain Next/Payload nên không được sửa.

CLI retrieval được chuyển sang runtime `tsx` đã có sẵn và đã được các script Payload trong project sử dụng. Live executor resolve module Payload/config khi được tạo, nhưng trì hoãn `getPayload()` và database pool đến query retrieval đầu tiên. Nhờ vậy bootstrap có thể được kiểm thử provider-free: module chain resolve thành công, executor được tạo mà không gọi Gemini và không khởi tạo/query database.

Fix không thay đổi query embedding, vector top 20, FTS top 20, RRF `k=60`, final top 6, dataset contract, call budget hoặc production decision policy. E1.1 không retry smoke E2 và không tiêu thụ embedding call.
