## 2. CLI contract

```text
npm run eval:chat:generation --
  --run-id <unique-id>
  --retrieval-artifact <absolute-path> [repeatable]
  --case-id <exact-id> [repeatable]
  --max-cases <positive-int>
  [--max-generation-calls <positive-int>]
  [--output-dir <absolute-path-outside-repository>]
  [--live]
```

- Mặc định là `DRY_RUN`; `--live` là opt-in rõ ràng.
- Case IDs bắt buộc explicit, không tự chọn/thay/thêm case và không truncate selection.
- `--retrieval-artifact` có thể lặp lại để exact batch dùng case từ E2 và E3 dưới **một ngân sách tổng**; duplicate run ID hoặc duplicate case ID giữa artifacts bị từ chối.
- Live mode bắt buộc `--max-generation-calls`; selection không được vượt `max-cases` hoặc call budget.
- Budget được kiểm tra trước mỗi call và đối chiếu physical call count sau call; khác 1 hoặc vượt tổng budget thì abort.
- Không có query rewrite, embedding, retrieval rerun hoặc automatic retry.
- Output directory phải tuyệt đối, ngoài repository và chưa tồn tại; artifact/file được tạo mới, không overwrite.

## 3. Generation evidence contract

Run-level artifact `generation-evidence.json` ghi:

- dataset version và source retrieval run IDs;
- model/embedding/ingestion/prompt/threshold versions;
- mode, maximum cases/calls, zero embedding/retrieval/query-rewrite/retry;
- eval-only policy version `eval-only-recorded-evidence-p5.7-e4-b1`.

Mỗi case ghi:

- case ID, expected decision, execution/result state và actual decision khi xác định được;
- source artifact run ID;
- S1–S6 context manifest gồm identity, URL và content hash khi đã hydrate;
- sanitized model output chỉ khi service cho phép ANSWER hoặc exact sentinel;
- citation validation, protected-output finding, physical call count, latency và sanitized error category;
- review record mặc định `NOT_EVALUATED`.

Raw provider error, credential, secret, session data và unvalidated provider output không được ghi.

## 4. Claim-level review contract

`generationReviewRecordSchema` tách riêng:

- answer correctness: `PASS | FAIL | NOT_EVALUATED`;
- claim text hoặc safe reference;
- cited S1–S6 label;
- semantic support: `SUPPORTED | PARTIAL | UNSUPPORTED | NOT_EVALUATED`;
- citation-to-claim grounding: `PASS | FAIL | NOT_EVALUATED`;
- forbidden-claim findings và reviewer rationale.

Harness khởi tạo mọi semantic judgment là `NOT_EVALUATED`. Citation label resolve không tự động biến grounding thành PASS; human review là bắt buộc.

## 5. Hydration safeguards

Live hydration (chưa chạy tại B1) sẽ:

1. Guard `DATABASE_URL` bằng existing Preview endpoint guard và database `neondb`.
2. Dùng exact `docType + docId + chunkKey` từ recorded final top 6.
3. Chạy `BEGIN READ ONLY`, một `SELECT` từ `rag_chunks`, rồi `ROLLBACK`.
4. Không gọi vector, FTS, RRF hoặc embedding.
5. Reject missing/duplicate/unexpected identity, URL mismatch, content rỗng và content-hash mismatch.
6. Giữ đúng order và gán S1–S6 qua existing production context shape.
7. Đóng Payload/database resource trước khi generation phase bắt đầu; cleanup chạy cả success và error path.
8. Dùng runner-only Payload config có `typescript.autoGenerate=false`, không mutate production config.

## 9. Known limitations và E4-B2 boundary

- B1 chỉ dùng mocks/dry-run; chưa chứng minh Neon live hydration hoặc Gemini behavior.
- Human semantic review chưa được thực hiện; review records vẫn `NOT_EVALUATED`.
- Offline evaluator hiện vẫn cần adapter/transform từ generation evidence nếu muốn tạo aggregate report trực tiếp; B1 không mở rộng evaluator production-free contract ngoài structured review record.
- `ans-001` vẫn là PARTIAL negative control; không tự đổi dataset decision hoặc threshold.
- Provider failure trong live mode sẽ ghi một sanitized failure case rồi dừng batch, không retry các case còn lại.

E4-B2 nên bắt đầu bằng read-only hydration preflight cho exact six cases, xác minh 1:1 identity/hash/order và resource closure với **0 Gemini calls**. Chỉ checkpoint sau đó, có owner approval riêng, mới được phép chạy tối đa 6 generation calls.
